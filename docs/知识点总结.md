## 第 1 课　外设就是一组寄存器

### 1.1 存储器映射

- STM32 把 Flash、SRAM、**外设寄存器**统一编进同一个 4GB 地址空间（0x0000_0000 ~ 0xFFFF_FFFF）。
- 分区分界：Flash 从 0x0800_0000 起，SRAM 从 0x2000_0000 起，外设从 0x4000_0000 起。
- **地址在芯片设计时就固定**，写在参考手册的「存储器映射」章节，不能自己安排。
- 库函数里的 `TIM2`、`GPIOA` 这些宏，本质是「把某个固定地址起个名字」。`TIM2->PSC = 71` 等价于「往 0x4000_0000 偏移某处的 4 字节写 71」。

### 1.2 写 1 为什么硬件会动

- 寄存器每一位直接连着硬件电路（门控、使能、分频选择……），写 1 就是给那条电路通电。
- **使能位通常在 `xxxENR`**：`RCC->APB1ENR` 的 TIM2EN 位写 1，定时器才拿到时钟和电源。
- 所以「忘了开时钟」的后果不是编译报错，而是**外设完全不动**——这是最耗时间的一类 bug。

### 1.3 HAL 库是翻译层

CubeMX 生成的 `MX_xxx_Init()` 就是一串「往哪个地址写什么值」。会看手册 + 会看 Init 函数，就能在 HAL 没有的功能上自己写寄存器。

### 1.4 DMA

- 作用：**不经过 CPU**，在外设与内存之间直接搬数据。
- 三要素：源地址、目的地址、传输数量；搬完产生**传输完成标志/中断**。
- 为什么需要：串口一秒来一千字节，CPU 逐个搬就把时间耗光了。

### 1.5 缓冲区与环形缓冲

- 缓冲区缓的是「**还没来得及处理的数据**」。不设缓冲区 = 处理速度跟不上，新数据覆盖旧数据（丢包）。
- 环形缓冲区：首尾相接的数组 + 读/写指针，适合持续到达的数据流。
- **读写指针重合时「满」和「空」看起来一样**，两种解决办法：
  1. 牺牲一个字节不用（满 = 写指针 +1 == 读指针）；
  2. 另设一个计数器记录当前元素个数。

## 第 2 课　时钟树

### 2.1 四个时钟源

| 时钟源 | 频率 | 用途 |
|---|---|---|
| HSI | 内部 8MHz RC | 备用、低成本场合，精度差 |
| **HSE** | 外部 4~16MHz 晶振 | **板载 8MHz 晶振走这条**，精度高 |
| LSI | 内部 40kHz | 独立看门狗 |
| LSE | 外部 32.768kHz | RTC 实时时钟 |

### 2.2 到 72MHz 的路径

```
HSE 8MHz → PLL ×9 → 72MHz → SYSCLK
   → AHB ÷1 → HCLK 72MHz
        → APB1 ÷2 → PCLK1 36MHz   （低速：TIM2~4、USART2/3、I2C）
        → APB2 ÷1 → PCLK2 72MHz   （高速：GPIO、USART1、ADC、TIM1）
```

- PLL 是锁相环，负责**倍频**；AHB/APB 是分频器。
- APB1 上限 36MHz、APB2 上限 72MHz，是因为挂载的外设速度需求不同，分开也能降低功耗。

### 2.3 最容易错的一条：定时器时钟 ×2

> **APB1 的分频系数只要不是 1，挂在 APB1 上的定时器时钟会被硬件自动乘以 2。**

所以 TIM2 的计数时钟是 **72MHz**，不是 36MHz。

- 按 36MHz 算 PSC → PWM 频率正好差一倍 → 舵机完全不认信号。
- 同理 TIM3、TIM4 也是 72MHz；TIM1 在 APB2（÷1），本来就是 72MHz。

### 2.4 核心公式

```
计数频率 = 定时器时钟 ÷ (PSC + 1)
PWM 频率 = 定时器时钟 ÷ (PSC + 1) ÷ (ARR + 1)
```

## 第 3 课　定时器

### 3.1 三个角色

| 寄存器 | 作用 | 一句话 |
|---|---|---|
| **PSC** 预分频器 | 把计数时钟变慢 | 决定「**多久数一下**」 |
| **CNT** 计数器 | 当前计数值 | 数到 ARR 就归零 |
| **ARR** 自动重装 | 数到几算一圈 | 决定「**一圈多久**」 |

### 3.2 更新事件与中断

- CNT 数到 ARR 后自动清零，这个动作叫**更新事件（UEV）**，是定时器的心跳。
- 想让 CPU 知道，就打开**更新中断（UIF/UIE）**。
- 计算示例：72MHz ÷ 72 = 1MHz（1µs 一次），数 1000 次 = 1ms → PSC=71、ARR=999 得到 1ms 定时中断。

### 3.3 中断为什么要短

- 中断里 `HAL_Delay` 会把 CPU 锁死：其他中断被挂起、主循环停摆，表现为丢数据、时序乱。
- 如果中断执行时间 > 中断周期，新中断得不到响应，实际频率被拉低。
- 正确做法：中断里只置标志/存数据，处理放到主循环（本作业的 `s_displayDirty` 就是这个思路）。

### 3.4 外部时钟模式

- 计数源从「内部时钟」换成「外部引脚信号」，数的不再是时间，而是**来了几个脉冲**。
- 典型场景：寻迹模块压线计数、编码器脉冲、外部事件频率统计。
- 入口：`ETR` 引脚，或某通道的 `TIx` 输入；引脚配成输入（浮空/上拉），定时器选外部时钟模式 1 或 2。
- 比「在中断里 cnt++」好在：**硬件计数不占 CPU，脉冲再快也不丢**。

### 3.5 从模式（Slave Mode）

「从」是相对**主机**说的 —— 主机可以是另一个定时器，也可以是外部信号（触发源）。

| 模式 | 触发信号来了做什么 |
|---|---|
| **复位模式** | CNT 立刻清零，从头数 |
| **门控模式** | 只有触发信号为高电平期间才允许计数 |
| 触发模式 | 把启动/停止权交给触发源 |

### 3.6 测一个方波的周期

让被测方波作触发源，用**复位模式**在每个上升沿清零：

```
周期 = 两个上升沿之间的计数值 × 计数周期
占空比 = 高电平期间的计数值 ÷ 总计数值
```

## 第 4 课　PWM

### 4.1 本质

不去改电压，而是**快速开关**；开关足够快，负载"感觉"到的是平均值。开的时间占比 = **占空比**。

### 4.2 四个参数

| 参数 | 含义 |
|---|---|
| 频率 | 一秒钟重复几次 |
| 占空比 | 每次高电平占多少（CCR ÷ (ARR+1)） |
| 极性 | 高电平有效 or 低电平有效 |
| 对齐方式 | 边沿对齐 / 中心对齐 |

### 4.3 关键关系

```
PWM 频率 = f_tim ÷ (PSC+1) ÷ (ARR+1)
CCR      = 占空比 × (ARR+1)
```

- 例：50Hz 时 ARR=19999 → 占空比 5% → CCR = 0.05 × 20000 = **1000**。
- **调角度改 CCR，频率固定不动**——这是舵机的铁律。

### 4.4 影子寄存器（预装载）

- 写完 CCR 不等于立刻生效，要等**更新事件**才把影子寄存器的值装载进去。
- 所以改完 CCR 发现没反应，先等一个周期再看。
- 这条在做舵机时能省半小时调试。

### 4.5 为什么频率差这么多

| 应用 | 频率 | 原因 |
|---|---|---|
| 舵机 | **50Hz** | 行业约定，每 20ms 给一次位置指令 |
| 直流电机 | **10~20kHz** | 高于人耳听觉上限，不啸叫；电流连续、转动平顺 |

反过来会出事：舵机收到 20kHz 会乱抖（不认信号），电机收到 50Hz 会一顿一顿地响。

## 第 5 课　舵机与直流电机

### 5.1 舵机：脉宽决定角度

| 脉宽 | 角度（180° 型） |
|---|---|
| 0.5 ms | 0° |
| 1.5 ms | 90°（中位） |
| 2.5 ms | 180° |

- 为什么是这个范围：几十年前航模时代留下的行业约定，至今没改。
- **1.5ms 是"中间"因为它是 0.5~2.5ms 的正中间**。

### 5.2 供电（最容易翻车的地方）

- SG90 堵转电流约 **700mA**；板子 5V 来自 USB，最多几百毫安。
- 从板子取电 → 启动瞬间把电压拉低 → 轻则抖动，重则单片机复位。
- **必须独立 5V（≥1A）供电，并且与板子共地**。不共地就没有共同 0V 参考，PA0 的高低电平对方判不出来，表现是"什么都不动"。

### 5.3 180° 与 360° 的区别

| 型号 | 脉宽含义 | 1.5ms |
|---|---|---|
| 180° 版 | 角度 | 中位 90° |
| 360° 版 | 转速与方向 | 停转 |

- 外观几乎一样，型号都印 SG90。
- **辨别方法：断电用手转舵盘**——只能转半圈是 180°，能一直转是 360°。

### 5.4 直流电机

- 不能直接用 GPIO 驱动：
  1. 电流不够（GPIO 十几 mA，电机几百 mA~几 A）；
  2. 电机是**感性负载**，断电瞬间反电动势会击穿 IO；
  3. 需要正反转，GPIO 单端输出做不到。
- **H 桥**：四个开关组成，通过导通组合实现正转/反转。
- 驱动模块引脚：
  - `ENA`：使能 + 调速，**接 PWM**
  - `IN1 / IN2`：方向，一高一低决定正反，同高或同低是刹车/停止
- 必须有**共地**，否则控制信号电平判断失效。

### 5.5 关键概念

- **堵转**：被卡住不转但仍通电，此时电流最大（可烧电机/舵机）。
- **共地**：两个电路共用同一个 0V 参考点。

## 第 6 课　蜂鸣器

| 类型 | 内部 | 驱动方式 | 效果 |
|---|---|---|---|
| **有源** | 自带振荡电路 | 给电平就响 | 音调固定，"只会叫" |
| **无源** | 只有电磁片 | 必须给方波 | 频率决定音调，"能演奏" |

- 快速辨别：直接给 3.3V/5V，响的是有源，不响的是无源；也可看背面是否有振荡电路/三极管。
- 无源变调的原理：方波频率 = 膜片振动频率 = 音调。
- **为什么要三极管**：GPIO 电流不够；且蜂鸣器有反向电动势，长时间直驱会损坏 IO。

## 第 7 课　编码器

- 输出 A、B 两路方波，**相位差 90°**（正交）。
- **判方向**：看谁超前。A 超前 B 是正转，B 超前 A 是反转。
- **四倍频**：A、B 的**上升沿和下降沿都计数**，一圈 N 个脉冲变成 4N 个，分辨率提高四倍。
- **编码器模式**：定时器专用模式，硬件根据 A/B 相位自动对 CNT 加减 1，CPU 只读不写。
  - 和 DMA 是同一个思路：**让硬件替你干活**。
- 转速换算：

```
转速(r/min) = (计数差 ÷ 一圈总脉冲数) ÷ 采样时间(s) × 60
```

## 第 8 课　串口拆包与上位机

### 8.1 两个麻烦

| 现象 | 成因 |
|---|---|
| **黏包** | 发送方连发两帧、中间无间隔，接收方一次读到两帧 |
| **拆包** | 一帧传输中被读走一半，剩下的下一轮才到 |

### 8.2 为什么必须用缓冲区

「收到一个字节就立刻处理」必然丢数据：处理速度跟不上来速，来不及处理的字节被下一个覆盖。循环缓冲区先把数据攒住，处理端按自己节奏取。

### 8.3 拆包状态机

```
等帧头 → 收长度 → 收数据 → 校验 → 交给上层
```

- **帧头的作用**：给接收方一个明确的起点，失步后能重新对齐。
- 工程上几乎不用"直接发一串 ASCII 数字"，因为没法可靠地拆回来。

### 8.4 上位机联调最容易对不上的四项

1. **波特率**（两边都设 115200）
2. **数据类型长度**（`int` 是 2 字节还是 4 字节）
3. **字节序**（小端/大端）
4. 帧格式里有没有校验位

调试阶段先发**定长数据**：字节数固定、解析简单、出错一眼看出在第几位；稳定后再改变长。

### 8.5 收到全是乱码，先查三样

1. 两边波特率是否一致；
2. 是否共地；
3. 时钟配置是否正确（时钟错 → 波特率偏差 → 表面"波特率对但就是乱码"）。

## 第 9 课　综合作业：PWM 驱动舵机定位

### 9.1 完整链路

```
时钟树算 PSC/ARR → 定时器出 50Hz PWM → 角度换算成 CCR
     → OLED 显示 → 串口打印 → 按键交互
```

### 9.2 引脚分配（避开冲突）

| 功能 | 引脚 | 理由 |
|---|---|---|
| 舵机 PWM | PA0（TIM2_CH1） | 不与外设冲突 |
| OLED | PB8 / PB9 | 软件 IIC，把 PB0/PB1 的 ADC 通道让出来 |
| 串口 | PA9 / PA10 | USART1 |
| 板载 LED | PC13 | 低电平点亮，可当"程序活着"的指示 |
| SWD | PA13 / PA14 | **绝对不能占用** |

**别碰 TIM4**：TIM4_CH1/CH2 正好是 PB6/PB7，那是 OLED 最常用的 I2C1 引脚，用了 PWM 就会"OLED 莫名不亮"。

### 9.3 三个必须自己算对的数

| 参数 | 值 | 算式 |
|---|---|---|
| PSC | 71 | 72MHz ÷ 1MHz − 1 |
| ARR | 19999 | 20ms ÷ 1µs − 1 |
| CCR(90°) | 1500 | 550 + 90 × 1900/180 |

### 9.4 两端限幅

- 名义 500~2500µs，实际取 **550~2450µs**。
- 原因：真实 SG90 行程比标称窄，打满会顶限位、堵转、发热。
- 550 与 2450 的中点正好 1500，中位不变。

### 9.5 评分点（自查清单）

| 项目 | 分值 | 要点 |
|---|---|---|
| 接线与供电 | 10 | 独立供电、共地可靠 |
| 时钟与定时器 | 20 | 72MHz 正确、50Hz 正确、PSC/ARR 推导对 |
| 角度换算 | 20 | 公式对、两端限幅、上电不顶限位 |
| OLED 显示 | 20 | 三行格式对、随角度变化、不闪不花 |
| 定角序列 | 15 | 五点依次到位、每点停顿 |
| 串口输出 | 10 | 与 OLED 一致、格式清晰 |
| 仓库与文档 | 5 | `.ioc` 在、无 build 产物、README 写了推导 |
| 扣分项 | — | 他人工程、板子取电、未共地、混入 build 目录，各扣 10 分 |

### 9.6 四个思考题（要能答）

1. **连发 0/45/90/135/180 不加延时**：舵机只会收到最后一个值（或乱跳），因为舵机内部有响应速度（约 0.1s/60°），根本没时间转到位。想匀速扫过去用**定时器中断逐步改 CCR**。
2. **二自由度云台**：两个舵机都要 50Hz，**同一个定时器的两个通道**（TIM2_CH1/CH2）即可，因为同一定时器共享 PSC/ARR，频率天然一致；各配一个定时器会浪费资源，且两个定时器的时钟/参数要各配一遍，容易不同步。
3. **0°→180° 用了多久**：约 0.3~0.6s（SG90 标称 0.1s/60°），**和 PWM 周期无关**。限制速度的是舵机内部电机与减速箱，不是信号。
4. **改成 DMA 发送**：`_write` 收到的 `ptr` 指向 printf 的内部缓冲，DMA 还没发完时下一次 printf 就可能改写它 → 发出半截或错数据。解决：**双缓冲/环形队列 + 等待上一次传输完成**（或用 `HAL_UART_Transmit_DMA` 前先拷贝到独立缓冲）。

| 黏包/拆包 | 两帧粘一起 / 一帧分两次 |
| 共地 | 共用 0V 参考点 |
| 堵转 | 卡住不转仍通电，电流最大 |

## 附录 C　排障速查

| 现象 | 最可能原因 | 怎么查 |
|---|---|---|
| 编译 `cannot open source input file` | 头文件路径没加 / 大小写不对 | 检查 `Core/Inc` 在 include 列表 |
| 编译过、下载成功但像没跑 | 卡在 `Error_Handler` 或时钟没配好 | `while(1)` 里翻转 PC13 看板载灯 |
| OLED 全黑 | SCL/SDA 接反、引脚定义没改、没供电 | 先跑 `IIC_CheckDevice(0x78)`，返回 0 才在线 |
| OLED 花屏 | 供电不稳、线太长、SCL 太快 | 换短线，加大 IIC 延时 |
| 舵机完全不动 | 没共地、信号没接 PA0、没 Start、CCR=0 | 示波器量 PA0 有没有 50Hz |
| 舵机一直抖 | 供电不足、频率不是 50Hz、超行程 | 换独立电源，先固定 1500 试 |
| 舵机某角度卡死 | 脉宽超 500~2500，顶限位 | 限幅到 550~2450 |
| 一接舵机单片机复位 | 从板子 5V 取电，启动拉低电压 | 独立供电，只共地 |
| PWM 频率差一倍 | 按 36MHz 算了，忘了 APB1 ×2 | 按 72MHz 重算 |
| 串口乱码 | 波特率不一致、没共地、时钟错 | 两边 115200，先发固定字符串 |
| 改了 CCR 没反应 | 没 Start、通道号错、还没等更新事件 | 确认 `HAL_TIM_PWM_Start`，等一周期 |

## 公式速查

```
计数频率   = f_tim ÷ (PSC + 1)
定时周期   = (ARR + 1) ÷ 计数频率
PWM 频率   = f_tim ÷ (PSC + 1) ÷ (ARR + 1)
CCR        = 占空比 × (ARR + 1)
舵机脉宽   = 550 + 角度 × 1900 ÷ 180        （0~180°，单位 µs）
转速(rpm)  = (计数差 ÷ 一圈脉冲数) ÷ 时间(s) × 60
```

72MHz 下常用组合：

| 目标 | PSC | ARR | 说明 |
|---|---|---|---|
| 1µs 计数 | 71 | — | 计数频率 1MHz |
| 1ms 定时中断 | 71 | 999 | 1000 次 = 1ms |
| 50Hz PWM（舵机） | 71 | 19999 | 20ms 周期 |
| 20kHz PWM（电机） | 71 | 49 | 50µs 周期 |
